## SWE-agent — verified boundaries

Source root: `researchs/swe-agent/repo/`.

1. **F04/F11/F15:** CLI/problem statements are intake, not Telegram/Butler routing. `sweagent/agent/action_sampler.py:54–93` labels sampled completions as colleagues, concatenates them and asks the same model to choose one action. It creates no independent colleague, message queue or chat session. `run_batch.py:268–287` uses a bounded local thread pool; `:333–374` constructs a new agent/environment for each independent problem and closes the environment in `finally`. This is bounded batch scheduling, not periodic project supervision. Report's Absent judgments are supported.
2. **F17:** `sweagent/environment/swe_env.py:85–98` constructs deployments through SWE-ReX. Controller→runtime calls are a real integration seam, but deployment implementations are external to the checkout. The report appropriately says Resembles and does not certify Mac/Endeavour coordination or multi-host organizational agents.
3. **F18/F19:** `sweagent/inspector/server.py:147–165` builds an action summary from commands; the saved trajectory and batch progress support detailed inspection, not an executive current/recent/next/blocker briefing. Report preserves the distinction and rates both Resembles.
4. **F22:** `sweagent/run/hooks/swe_bench_evaluate.py:43–64,107–122` actually invokes external `sb-cli submit` and moves its report on successful completion. This is stronger than testing prose alone, but limited to supported benchmark subsets. Submission exit status is not product acceptance. The report accurately distinguishes a patch, optional draft PR and benchmark evaluation from integrated product DoD.
5. **Lifecycle identity/cleanup:** `sweagent/agent/agents.py:501–514` deep-copies configuration but omits `name` when constructing `DefaultAgent`; `run_batch.py:336` assigning configuration name therefore does not establish individual persistent identities. `run_single.py:188–207` closes only on its normal end; batch cleanup is separately protected. Report correctly documents both instead of asserting guaranteed cleanup or durable employee state.
6. **Major extras/innovation:** Report covers dataset/benchmark execution, model-scored whole attempts, action candidate search, replay/demonstrations, visual task tools and the EnIGMA revision caveat. It does not invent a distributed manager from RetryAgent or independent collaborators from AskColleagues.

Searches of runtime/config/tool paths for Telegram, cron, heartbeat, rooms, summary and timeline found no overlooked organization runtime. This negative search complements the concrete runner/action-sampler/Inspector/evaluation paths, rather than relying on README silence.

## AgenTopology — verified boundaries

Source root: `researchs/agentopology/repo/`.

1. **Actual execution:** `src/cli/index.ts:850–857` explicitly says `plan` cannot spawn subagents and does not run anything. `:875–905` stores the selected autonomy mode in an execution brief, and `:963–964` prints that brief. 2. **F04:** `src/bindings/openclaw.ts:351–410` emits external channel configuration, including Telegram fields; `:484–495` routes each configured channel to a default/first agent in generated JSON. No transport or project-question correlation is implemented here. Report's Resembles judgment and explicit external-platform boundary are supported.
3. **F11:** `src/bindings/claude-code.ts:1062–1067,1198–1240` generates transcript-based group instructions and sequential host spawning. This is a meaningful discussion protocol with host ordering as the lock. It is neither an asynchronous room service nor a chat application. Report says exactly that.
4. **F15:** `src/bindings/openclaw.ts:414–416,519–530` enables cron and emits isolated `agentTurn` jobs, using `job.cron ?? job.every` directly with `kind: cron`. The report correctly retains compatibility uncertainty for human-readable `every` values. `src/bindings/codex.ts:595–607` renders schedules as documentation. `src/plan/brief.ts:245–264` identifies persistent platform registrations that fileless interpretation cannot supply. No ProjectMaster blocker-follow-up algorithm is hidden in these paths.
5. **F17/F18/F19:** Portable target files, model endpoints, static topology analysis and brain visualizations do not provide remote host dispatch or a live executive feed. Report's Absent findings are consistent with the local AST/binding/CLI/plan architecture and searches.
6. **F22 — placeholder-success hazard:** `src/bindings/lib/stub.ts:49–59` emits a shell stub containing only strict mode and `echo TODO`, with no nonzero exit. Generated Claude gate wrappers do execute commands/retry/time out and react to nonzero status (`src/bindings/claude-code.ts:2080–2113`), but a generic untouched stub can still succeed without checking anything. Report explicitly captures this and distinguishes failing action placeholders from generic gate stubs. This is a verified boundary, not a proposed source patch.
7. **Lifecycle and failure policies:** `src/bindings/codex.ts:703–736` renders timeout/retry/join/rate-limit/circuit-breaker/compensation fields as instructions. These declarations are not services or runtime recovery state. Report separates role definitions, generated files, host execution contexts, artifact evidence and session continuity, and covers retirement as scaffold cleanup.
8. **Major extras/innovation:** The report covers portable compilation and import/sync, ownership-aware regeneration, graph validation and diagrams, knowledge modeling, and hybrid Workflow loss accounting. Its information-flow/gate-placement/evidence-model mechanisms are source-grounded and do not claim industry uniqueness.

## Zeroshot — verified boundaries

Source root: `researchs/zeroshot/repo/`.

- This checkout is the Rust v8 product, not retired Node-era Zeroshot. Checkout `AGENTS.md` explicitly identifies `zeroshot/` as canonical and forbids recreating the retired product. Any report based on old Node topics/message-bus roles would require replacement.
- `zeroshot/src/native_v2_templates.rs:88–119,197–223,226–277,325–347` constructs a real software-change graph: one implementation/repair worker, parallel acceptance and code verifiers, and bounded repair routing. Tests/checks are requested in authored instructions, while verifier signals drive native routing. This is materially stronger than AgenTopology's printed execution prescription.
- `ui/src/ExecutionTimeline.tsx:12–54` derives an ordered execution strip from node/label/state/signals. `ui/src/StandaloneRuns.tsx:22–31,74–91` lists and polls run summaries. These are run/node observability and playback, not semantic per-agent current/recent/next/blocker executive briefings or an enduring agent summary feed. F18/F19 require that distinction even though real timelines exist.
- **F04/F11/F15:** Production engine/UI searches found no Telegram/Butler or periodic organization wake service. `zeroshot/src/native_v2_supervisor.rs:273–325` repeatedly reduces an admitted graph, dispatches and awaits completion; it does not inspect a portfolio or send a blocked specialist a conversational follow-up. Typed feedback/shared files are genuine coordination primitives, without participant-addressed peer rooms. Report correctly uses Absent for F04 and Resembles for F11/F15.
- **F17:** `zeroshot/src/native_v2_cli/oecp.rs:279–287,310–364` actually delegates named-target submission and connects to per-run status/watch transports. `zeroshot/src/native_v2_candidate.rs:1–5,51–57` composes all lane adapters against one run workspace. The report appropriately credits remote execution as Similar while rejecting graph-node host distribution or shared organizational rooms/tracker. It does not conflate local subprocesses with remote hosting.
- **F22:** `zeroshot/src/native_v2_templates.rs:514–520` requires both acceptance and code signals to accept; `:325–347` routes execution errors to failure and ordinary rejection to repair. Real state-machine gates exist, but test execution quality and independent reviewer correctness remain model/harness dependent. Report preserves the distinction between a native delivery receipt, model acceptance and human whole-product acceptance.
- **Lifecycle continuity:** `zeroshot/src/native_v2_runner/state.rs:223–258,285–318` distinguishes fresh execution scope from reusable node-instance scope and fails closed for a passively lost session. `zeroshot/src/native_v2_cli/local/backend.rs:20–50,79–105` claims retained state, records predecessor/successor lineage and starts a new controller. Local workspace discard is explicitly refused at `:384–392` because the workspace belongs to the user. The report accurately distinguishes conversational reuse, durable ledger/workspace state and fresh failed-run successors; it does not claim old conversations are checkpointed.
- **Checkpoint/finalization:** `zeroshot/src/native_v2_supervisor.rs:329–340` captures only quiescent boundaries; `:344–364` latches the primary result, closes sessions, handles checkpoints, performs cleanup, appends terminal truth and retires successful checkpoint storage. Report's lifecycle sequence matches those paths and avoids claims about restored live services/databases.
- **Major products/extras:** The final report covers host-based proportional research/clarification through a planning skill. This does not supply a resident ProductMaster. It covers typed graph verification, trusted GitHub/GitLab delivery and Restic recovery. Scoped Active Memory includes four maintenance/discovery roles. Other coverage includes auto-research, PR review/comment publication, native harness lanes, scripts/decision leaves and experimental ACP conversation reuse. These are substantial capabilities beyond Wingman's stated organization; none was omitted in favor of only a simple worker/validator description. The report explicitly bounds hosted Platform as a separate integration and avoids asserting deployment availability.
