## Correction requiring a qualification

**multi-agent-shogun, F15 and recovery prose: distinguish the standalone watcher-supervisor utility from the default launch path.** The report correctly says its supervisor restarts missing watchers every five seconds, but currently presents this beside normal runtime behavior without saying whether it starts. [watcher_supervisor.sh](../../../multi-agent-shogun/repo/scripts/watcher_supervisor.sh), lines 34–59 and 89–92, implements that behavior *if separately running*. A repository-wide search for `watcher_supervisor` finds no checked-in runtime caller: the standard [launcher](../../../multi-agent-shogun/repo/shutsujin_departure.sh), lines 893–939, directly launches individual watchers, then proceeds to other steps; it does not launch this supervisor. The other reference outside the script is the `.gitignore` exception. Consequently, default-launch self-repair by this utility is not established.

Suggested correction: “An optional standalone supervisor utility can restart missing inbox watchers every five seconds; no invocation from the standard launcher was found. The standard launcher directly starts the watchers.” Apply the same qualification to the supporting audit's final recovery paragraph. Keep the existing, correct boundary that watcher recovery does not recreate a dead coding agent or perform semantic project supervision. This is a wiring qualification, not a reason to change the overall verdict.
