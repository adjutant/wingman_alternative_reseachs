## Findings and resolution

1. **AgentRail F19: distinguish replay retention from disk retention (minor).** The matrix says “event retention is 72 hours.” `src/task-event-store.ts:101–114` prunes only `_events` in memory; `142–150` loads/appends the JSONL disk file without truncating it. The architecture prose already correctly says a 72-hour in-memory replay window. Change the matrix to “API/in-memory event replay is limited to 72 hours.” This does not change Resembles: there is still no cross-run agent summary timeline UI.
2. **Sortie F22 + F17 interaction: checks execute on the controller filesystem (material deployment boundary, not a false core verdict).** `internal/orchestrator/self_review.go:178–215` verifies a local directory then invokes local `sh -c` with `cmd.Dir=workspacePath`. `worker.go:1717–1745` passes the workspace path and session to the self-review loop, without an SSH-aware verification executor. In contrast `internal/agent/codex/codex.go:470–479` builds an SSH launch for the coding session. Thus a real remote coding session does not by itself establish that configured self-review checks ran against remote changed files. Add this specific boundary to the existing remote workspace assumptions or verification paragraph; separately synchronized/shared contents can change the deployment outcome. Existing Similar F17/F22 verdicts remain justified.

Both findings were sent to the parent and corrected by the report owners. I rechecked the resulting AgentRail F19 row and Sortie F22/lifecycle/practical-fit additions. Neither requires a feature-grade change. No unresolved material correction remains.
