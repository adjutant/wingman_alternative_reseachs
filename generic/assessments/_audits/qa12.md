## Corrections and clarifications

### CAO F03: distinguish API relationships from visible working relationships

The current F03 statement calls CAO an operational fleet directory “with parent/group relationships,” citing the terminal model, the `SupervisorDashboardStream` fold, and the browser dashboard. Creation/group relationships do exist in data: [terminal.py](../../../cli-agent-orchestrator/repo/src/cli_agent_orchestrator/models/terminal.py), lines 143–155 and 172–185. However, the browser dashboard uses session membership and profile/status filters: [DashboardHome.tsx](../../../cli-agent-orchestrator/repo/web/src/components/DashboardHome.tsx), lines 78–183 and 380–440. Searches of `web/src` found no rendering of `caller_id`/`callback_terminal_id` or the terminal grouping array as working relationships. The generic select widget's `group` is unrelated UI option grouping.

[supervisor_dashboard.py](../../../cli-agent-orchestrator/repo/src/cli_agent_orchestrator/services/agui/supervisor_dashboard.py), lines 53–65 and 129–178, is a reusable fold class; searches found its consumers in exports/documentation rather than a bound application view. Its `hierarchy()` groups by session, not creator/manager relationships. The separately named topology app is explicitly a minimal SSE event log, not a fleet relationship visualization: [topology.js](../../../cli-agent-orchestrator/repo/src/cli_agent_orchestrator/ext_apps/static/topology.js), lines 1–3 and 16–39.

Recommended correction: say **“a visible session/profile roster with API-level creator/group metadata; visible organizational or creator relationships were not established.”** F03's `Similar` can be retained only with this explicit partial boundary; `Resembles` is also defensible for the full directory-and-working-relationships requirement. This does not undermine CAO's real fleet dashboard, which the report correctly credits elsewhere.

### multiclaude message retry wording

The coordination section says delivered messages are “not retried until acknowledged.” That phrasing can imply acknowledgment enables a retry. The router only injects `pending` records and skips all other statuses: daemon.go (excluded historical source: `multiclaude/repo/internal/daemon/daemon.go`), lines 390–415. Replace with **“successful terminal submission marks a message delivered; delivered messages are not automatically reinjected, and read/ack are separate operations.”** The report already correctly explains that terminal delivery is not proof of model receipt or action. This is a wording correction, not a feature verdict change.
